## 3. Current contract behaviour (SOURCE REVIEW unless stated)

1. `/ingest` always returns HTTP 200 `{accepted:[…], rejected:[…]}`; duplicates are
   reported as `rejected` with reason `"duplicate packet_id"`. Mobile classifies a
   `rejected` entry starting with `duplicate packet_id` as **duplicate ⇒ delivered ⇒ ACK**.
2. Dedup key is `packet_id` alone (`is_duplicate`), checked **before** signature
   verification. A forged, unsigned packet with a victim's `packet_id` is stored
   (status EXPIRED / REJECTED_SIGNATURE, occupying the UNIQUE `packet_id`), after which the
   genuine packet is answered `duplicate packet_id`.
3. Expiry: `is_ttl_expired(max_age_seconds=3600)`; Dart mesh `maxPacketAge` = 5 min
   (receive/relay side); AI cluster window `TIME_WINDOW_SECONDS` = 300 s; backend fallback
   dedup window 15 min / 150 m; AI geo radius 500 m.
4. `ingest.py` computes `age_seconds` with `datetime.fromisoformat(ts).timestamp()`,
   which treats a naive timestamp as *local* time (and is inconsistent with the UTC
   assumption in `is_ttl_expired`).
5. `PacketType` has no `ack`/`alert`; those packet types (Dart) are mesh-only, are excluded
   from the durable upload queue (`_isUploadable`) and `_tryUpload` (Block 1).
6. ACK is generated by the Dart client after it interprets the `/ingest` response
   (`accepted`/`duplicate`); it is signed by the *uploading* device, not by the backend.
7. AI dedup: `matched_cluster_id` (an emergency_id) → `_find_incident_by_emergency_id`
   which does **not** check incident status → a CLOSED incident can silently absorb a new
   emergency. No category or backend-side geographic check on the merge.
   Cluster state is in-memory and per-process.
8. `IncidentOut` exposes only id/type/lat/lon/status/hop_count/created_at/closed_at.
   Dashboard `normalizeIncident` reads `sender_priority`, `ai_*`, `relay_path` → always
   empty against real data. `AuditLogOut` lacks `id`, which the dashboard reads.
9. SMS: backend gateway SMS on new incident (needs registered profile contacts) **and**
   mobile direct SMS on every SOS, unconditionally. Backend send has no idempotency
   record; logs full destination number and (when unconfigured) full message body.
10. `GET /alerts/nearby` is unauthenticated, returns all OPEN incidents within ≤15 km of
    any supplied point.
11. Missing `X-API-Key` header ⇒ FastAPI 422 (not 401).
12. Voice: `emergency_id`/`sender_id` accepted as-is; `latitude/longitude` floats not range
    checked (500 risk on bad float / PacketIn validation error is uncaught ⇒ 500);
    file suffix allow-list only; whole file read into memory before size check.
13. Two AI trees: `Backend/setu_ai_service/` (imported at runtime, 38 tests) and
    `setu_ai_service/` (root, older copy, `test_models.py` empty, no importer).
